RESOLVED POLICY:
- Fixed versioned app prefix in Global namespace, scoped by effective current user's Windows SID. For credentials use effective token identity, not arbitrary username/environment value. Obtain validated SID using documented APIs (query thread token then fall back only on ERROR_NO_TOKEN to process token, or equivalently documented effective token approach). Do not print SID/token/security descriptor. Preserve backing-buffer lifetimes and alignment; avoid unaligned TOKEN_USER dereferences.
- Explicit security descriptor owner = that user SID; protected DACL with exactly one non-inherited access-allowed ACE granting that SID MUTEX_ALL_ACCESS, no other grant. Numeric ACE mask derived from actual binding constant, not ambiguous generic GA mapping. Use SDDL construction/conversion or documented ACL builder. This is for OUR mutex, not a change to any user file/otherobject. No admin request, Everyone/Users/worldgrant/defaultDACL/silentLocal fallback.
- CreateMutexExW desired handle rights minimal SYNCHRONIZE|MUTEX_MODIFY_STATE|READ_CONTROL, not ALL_ACCESS. bInheritHandle false, no initial ownership, explicitattributes. Every returned object (new OR existing) inspected through actual handle GetSecurityInfo before waiting: valid descriptor, owner EqualSid currentSID, protected and present/non-null DACL, exactly matching single explicit allowed ACE/SID/mask. Reject unexpected owner/extraACE/inheritance/nullDACL/mask/type. Validate native descriptor/ACL/ACE/SID structure and bounds before unsafe dereferences. Do not trust ERROR_ALREADY_EXISTS alone; creation attributes don't repair existing objects. Do NOT modify/delete an incompatible preexisting object, just close/fail staticstorageerror. Other-user name squatting may cause denial-of-service; it must not grant secret access or bypasslocking. Same-user malware/admin remains outside protection boundary, as it already can read currentuser genericcredentials.
- Bounded 10second wait. On WAIT_OBJECT_0 return RAII guard; Drop releases ownership then closes handle. Guard must NOT be Send/Sync because Windows ownership belongs to acquiring thread. On WAIT_ABANDONED ownership WAS acquired: release/close and return sanitized error WITHOUT any persistent-state operation. Later explicit retry can reacquire and validate storage; no pretend recovery. Timeout/WAIT_FAILED/unexpected return close safely and fail sanitized error, no Local fallback. RAII for token/localalloc/object resources on every failure. No secrets/paths/nativeWindows diagnostic strings to stdout.
